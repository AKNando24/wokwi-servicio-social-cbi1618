# Guion 9.2 — Visual Studio Code, PlatformIO, extensión de Wokwi y librerías propias

**Módulo:** 9 · **Duración estimada:** ≈ 10:50 min en total (locución ≈ 5:52 min a 140 palabras/min, más demostración en pantalla)
**Archivos que se muestran:** carpeta `9.2_platformio_vscode/` completa: `platformio.ini`, `wokwi.toml`, `diagram.json`, `src/main.cpp` y `lib/EstacionLib/`
**Objetivo del alumno:** montar un proyecto profesional con PlatformIO, simularlo con la extensión de Wokwi, declarar dependencias en `platformio.ini` y crear una librería propia reutilizable.

**Antes de grabar:** ten instalados VS Code, la extensión PlatformIO IDE y la extensión Wokwi for VS Code con la licencia activada (F1 → «Wokwi: Request a new License»); compila el proyecto una vez antes de grabar para no esperar las descargas. Si pasa de 10 minutos, dividir tras la escena 6.

---

### Escena 1 — Gancho (0:00–0:45)
**Pantalla:** VS Code con el árbol del proyecto, el botón de compilar y la simulación ejecutándose.

> El editor web de Wokwi es perfecto para aprender, pero cuando un proyecto crece, necesitas herramientas profesionales: autocompletado, varios archivos, control de versiones, bibliotecas propias. Hoy vas a configurar un entorno de desarrollo real: Visual Studio Code con PlatformIO para compilar, y la extensión de Wokwi para simular el resultado, sin salir del editor. Al final tendrás un proyecto con una librería propia que podrás reutilizar en cualquier otro.

### Escena 2 — Las piezas del entorno (0:45–2:00)
**Pantalla:** diagrama de tres piezas: VS Code, PlatformIO y Wokwi.

> Son tres piezas que trabajan juntas. Visual Studio Code es el editor: gratuito, extensible y muy popular. PlatformIO es una extensión que se encarga de compilar: descarga el compilador adecuado para tu placa, administra las librerías y genera el firmware. Y la extensión de Wokwi simula ese firmware con el circuito que describe tu diagram punto json. Fíjate en la división de trabajo: Wokwi no compila tu código. Primero compilas con PlatformIO, y después Wokwi simula el resultado. Para activar la extensión de Wokwi necesitas una licencia, que se solicita desde la paleta de comandos, con F1 y la opción Wokwi dos puntos Request a new License; el proceso te lleva a tu cuenta de Wokwi y revisa en ese momento las condiciones vigentes.

### Escena 3 — Estructura del proyecto (2:00–3:20)
**Pantalla:** árbol de carpetas con `src`, `lib`, `platformio.ini`, `wokwi.toml` y `diagram.json`.

> Veamos la estructura. En la carpeta src vive tu programa principal, ahora en un archivo main punto cpp, que es C más más puro en lugar de un sketch. Lo primero que se agrega es la línea include de Arduino punto h. En lib van las librerías propias, cada una en su carpeta. En la raíz, platformio punto ini, que describe el proyecto; wokwi punto toml, que le dice a la extensión qué firmware simular; y diagram punto json, el mismo archivo que ya conoces. Esta organización es la misma que usa cualquier proyecto profesional de firmware, y facilita trabajar en equipo y usar Git.

### Escena 4 — platformio.ini (3:20–4:50)
**Pantalla:** resaltar `platform`, `board`, `framework`, `monitor_speed` y `lib_deps`.

> El archivo platformio punto ini es el corazón del proyecto. Cada sección entre corchetes es un entorno. El nuestro se llama uno. Indicamos la plataforma, atmelavr, la placa uno y el framework arduino. La velocidad del monitor serie a ciento quince mil doscientos. Y lib_deps, la lista de dependencias: aquí declaramos la librería de Adafruit para el DHT, con una versión mínima, y la unificada de sensores. PlatformIO las descarga solas la primera vez, y quien clone tu proyecto obtiene exactamente las mismas versiones. Esto resuelve el viejo problema de «en mi computadora sí funcionaba».

### Escena 5 — Compilar y simular (4:50–6:20)
**Pantalla:** botón Build de PlatformIO; salida en la terminal; F1 → «Wokwi: Start Simulator».

> Ahora compilamos con el botón de la barra de PlatformIO, o desde la terminal con pio run. Los archivos resultantes quedan en la carpeta oculta punto pio, dentro de build y el nombre del entorno: ahí está el firmware punto hex y el firmware punto elf. Nuestro wokwi punto toml apunta a esos dos archivos. Con F1 y Wokwi dos puntos Start Simulator, se abre el circuito dentro de VS Code y arranca la simulación, con el monitor serie incluido. Y una comodidad: cada vez que recompilas, Wokwi recarga automáticamente el nuevo firmware.

### Escena 6 — Crear una librería propia (6:20–8:20)
**Pantalla:** mostrar `EstacionLib.h` y `EstacionLib.cpp`; explicar las clases `FiltroMedia` y `Umbral`.

> Aquí viene lo mejor: crear nuestra propia librería. En lib creamos la carpeta EstacionLib con dos archivos. El archivo de cabecera, punto h, declara qué ofrece la librería: dos clases. FiltroMedia calcula un promedio móvil de las últimas ocho lecturas, con un arreglo circular, sin memoria dinámica. Umbral compara un valor contra un límite con histéresis, el mismo concepto que aplicamos al extractor del Módulo 4, pero ahora empaquetado y reutilizable. El archivo punto cpp contiene la implementación. Fíjate en el protector de inclusión, con ifndef y define, que evita que la cabecera se incluya dos veces. PlatformIO detecta automáticamente toda carpeta dentro de lib, sin ninguna configuración adicional.

### Escena 7 — Usar la librería (8:20–9:30)
**Pantalla:** `main.cpp` con `#include "EstacionLib.h"`, los objetos `filtro` y `alarma` y la salida CSV.

> Usarla es sencillo: incluimos el archivo, creamos un objeto FiltroMedia y un objeto Umbral con una histéresis de uno punto cinco grados. En el loop, cada segundo leemos el DHT22, agregamos la lectura al filtro, calculamos el límite desde el potenciómetro, entre veinte y cuarenta grados, y le preguntamos a Umbral si la alarma está activa. El programa principal queda corto y claro, porque la complejidad vive en la librería. Y la salida es una línea CSV por segundo, lista para pegar en una hoja de cálculo y graficar.

### Escena 8 — Librerías en la versión web y buenas prácticas (9:30–10:20)
**Pantalla:** el editor web con los archivos `.h` y `.cpp` agregados al proyecto; lista de buenas prácticas.

> ¿Y en el editor web? Allí no existe la carpeta lib, pero puedes añadir tus archivos de cabecera y de implementación al proyecto con la opción de nuevo archivo, y el compilador los encuentra. Para librerías públicas, usas libraries punto txt. Algunas buenas prácticas para cerrar: fija versiones en lib_deps para que el proyecto siga compilando dentro de un año; agrega a tu gitignore la carpeta punto pio, que es generada; y nunca subas al repositorio claves ni contraseñas.

### Escena 9 — Resumen y reto (10:20–10:50)
**Pantalla:** resumen y reto.

> Resumiendo: PlatformIO compila, Wokwi simula; platformio punto ini declara placa y dependencias; wokwi punto toml apunta al firmware; y una librería propia en lib empaqueta código reutilizable. Tu reto: añade a EstacionLib una función que devuelva la tendencia, si la temperatura sube, baja o se mantiene. En el siguiente video armamos el proyecto integrador: una estación meteorológica completa.
